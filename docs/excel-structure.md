# 旧Excelの作り（解析メモ）

アプリに置き換える前の、4本のExcel・マクロの作りをまとめたもの。ふだんはこのメモを見て、Excel原本は不明点が出たときだけ開く。
取引先の実データ（社名・金額・住所）はここには書かない。企業ごとの事情は、claude.ai プロジェクトの引き継ぎメモにある。

最終確認：2026-10-28（社内申込書は 20261026 版）

## 全体の流れ（旧Excel）

1. **社内申込書**：企業ごとのシートに、その月の請求明細を書く（セレッジ側で決まった内容。柏木さんが入力していた）
2. **売上表**：月別シートに転記し、「請求書へ」ボタン（マクロ）で請求書を作る
3. **売上・支払一覧**：売上表から手で転記し、収支概算を手で集計する
4. **月末支払い管理**：受け取った請求書を登録し、支払いシートへ転記する

手で書き写す段が多く、そこで入力ミスが起きていた（下の「入力ミスの実例」）。

## 1. 社内申込書（.xlsm）

- **請求内容と住所の正**。取り込みはこのファイルを基にする
- 企業ごとに1シート（約60枚）。ほかに「目次」「申込書」「Sheet1」「データ」がある
  - 「Sheet1」：企業の住所一覧（郵便番号・住所・部署・担当者）
- 企業シートの明細は、単価と個数が別の列にある
- 企業ごとにマクロが1本ずつある（51本）。新しい企業のたびに柏木さんが追加していた
- 品名の書き方がそのまま請求書に出る。主なパターン：
  - 回数つき：「◯名：在留サポートサービス費用（5回目/全24回）」
  - 月分つき：「◯名分：在留サポートサービス：11月分」
  - 両方：「在留サポートサービス費用：10月分（14回目/全24回）」
  - 月数：「二期生在留サポートサービス費用（11月分）27か月目」
- 取り出しの規則は `tools/extract_import.py` に書いてある（表記ゆれの吸収、毎月の契約の見分け方）

## 2. 売上表（.xlsm）

- シート：「アジア請求書」「Sheet1」と、月別シート（11月〜翌9月）
- 月別シートの上部：1行目 B列＝請求日、2行目 B列＝社名、3行目＝「請求書へ」ボタン
- 5行目が見出し：担当／社名／請求書№／商品名／発売日／スペース／受注金額／制作料等／請求書確認／掲載原価／制作原価／利益／Qあき状況／入金予定
- **A列「担当」の★**：郵送せず、セレッジ担当がメールで直接送る請求書の印。付く企業は月によって違った（いまは「送り方は請求書ごとに選ぶ」に置き換え）
- 上半分は広告枠の名残で、使わない
- 「請求書へ」マクロは「8月」シートを名指ししていて、月ごとに手直しが要る作りだった
- 角印の画像はこのファイルの中（`xl/media/image1.png`、902×902、背景透明）。GitHub には入れない
- 同じ企業・同じ月の2枚目は、社名の末尾に「1」「2」を付けて区別していた（アプリでは表記ゆれとして企業に結びつける）

## 3. 売上・支払一覧（.xlsx）

- 売上表から手で転記する一覧と、収支概算
- 支払い側に「支払い」シートなど。定例の支払い先には名前の末尾に★が付いている（毎月の定例支払いの印。売上表の★とは意味が違う）
- 家賃は独立したシートがある（アプリでは支払いとして扱う）

## 4. 月末支払い管理シート（.xlsx）

- 受け取った請求書を月末にまとめて登録し、支払いシートへ転記する
- 総務を通さない支出（カード・引き落とし）もある

## 請求書の書式（旧Excelの請求書）

- 宛名は「社名＋御中」だけ（住所は封筒用）
- 明細は8行。内定日の列は常に「－」
- 立替金（航空券など）は品名に「（非課税）」と書くだけで、税額は手で直していた
- 消費税の端数は切り上げ

## 入力ミスの実例（アプリで防ぐもの）

- 年が1年ずれた請求日（例：2025/12/31 のはずが 2026/12/31）
- 請求書番号の重複（同じ月に同じ番号が3枚）
- 請求日と計上月のずれ
- 確認用Excelの日付の打ち間違い（「202512/31」など）。取り込みツールは数字だけ読んで解釈する

## 入金の実態

- 1回の振込で、複数の請求書・複数の月をまとめて払うことがある
- 不足入金もある
- 翌月分を前請求する契約が多い（10月末に11月分を請求する）
