決まっていないことは、仮のルールで固めずに聞く（最後の「まだ決めていないこと」）。
企業ごとの個別の事情は、claude.ai プロジェクトの引き継ぎメモにある（取引先の実データなので GitHub には置かない）。
設計書：Claude Docs「セレッジ管理システム」の「設計 v1.0（3つの目的）」タブ。

## 呼び名（11/01 ひろみ統一）

会話・コード・画面・資料はすべてこの名前で呼ぶ。

| 呼び名 | もとのファイル | 中身 |
| --- | --- | --- |
| **企業シート** | 社内申込書（.xlsm） | 企業ごとのシート。請求の予定表（先付けあり） |
| **売上表** | 売上表（.xlsm） | 請求日ごとの月別シート |
| **収支一覧** | 売上・支払一覧（.xlsx） | 売上明細（「請求」シート）・収支概算・支払い など |

## アプリの目的（2026-10-29 確定。いちばん大事）

1. **入力フォーム**：請求の内容を入れる窓口
2. **各Excelへの転記**：企業シート・売上表の月別シート・収支一覧の売上明細に行を足す
3. **請求書の作成**：入力した内容から、企業ごとの請求書を作る

- 総務への請求書依頼はなくなる。入力した人がそのまま請求書を作る
- 申込書シートの作成も、企業ごとのマクロも使わない。旧Excelの段階を置き換えようとせず、この3つから考える
- **Excelは今の形のまま使い続ける**（税理士に出す形を変えない）。収支一覧だけは、ひろみの了承のうえで新しい形にする
- 内訳（案件名）の書き方のルールは作らない。項目欄だけ用意し、書き方は入力者に任せる。明細は何行でも足せる
- 入金確認と支出は、今までどおりひろみがExcelで入力する。アプリに入金・支出の画面は作らない
- 契約ごとの請求状況の一覧は、確認用のサマリとして残す

## 企業シートの先付けとフォームの履歴（11/01 ひろみ決定）

- **企業シートは請求の予定表**。継続の企業は、先の月の行まで先付けで書いてあることがある。書いてある＝請求書を発行した、ではない
- フォームで企業を選ぶと、その企業の請求の履歴が**月ごと**に、たたんだ状態で出る（開くと見える）。列は 請求対象月｜金額｜状態｜操作
- フォームの履歴の状態は **請求済み／未請求** の2つだけ（長い言葉は出さない。場所まで書いた細かい状態は、請求ごとの画面に出す）
  - 請求済み：その行の請求書を発行した
  - 未請求：企業シートに書いてある（先付け）が、請求書はまだ発行していない
- 未請求の月から **新規** で請求を作る。アプリに入れかけの請求がある月は **開く**（同じ月に2枚作らないため）
- 履歴に入力した内容は、Excelに記入されたあと、また履歴の状態に出る

## フォームで完結し、企業シートは書くだけ（11/01 夜 ひろみ決定）

- 11月からの請求は、**フォームで完結**する。企業シートへの先付けの手書きはしない。アプリが企業シートに**書き込むだけ**で、ふだんの運用で企業シートを読むことはない
- 実務の担当者（当面はセレッジの社長）が、アプリだけで請求を終えられることを目指す
- 過去の分（10/31 まで）は、企業シートから**最初に1回だけ取り込む**（「企業・契約」→「企業シートの取り込み」）。企業を選ぶと、その企業の過去の請求がすべて履歴に出る
  - 取り込みはブラウザの中でファイルを読み、行（請求日・案件名・金額など）だけをサーバーに送る。取り込み直すと、取り込み済みの行は入れ替わる
  - アプリに登録していない企業のシートは取り込まない
- **請求済みの線引き**：企業シートの請求日が **10/31 以前の行はすべて請求済み**（設定 `legacy_billed_until`）。11/01 に、企業シートの10月の行と売上表 10月シートの行が、案件名・金額で全行一致することを確かめた
- **計上月**：企業シートの行は、請求日の月を計上月にする（H列の計上月は手書きでずれることがあるので使わない）。フォームでは計上月を自動で出すが、**手で直せる**（売上の少ない月に翌月分を前に移すことがあるため）
- **単価**：人数で数えるとき（人材紹介1人につき、1名あたり月◯円など）に使う。一時金・調整金のように人数で数えない行は、**単価に金額を入れて個数1**にする（11/02 ひろみ決定。11/01 の「単価を空けて金額だけ」は作らない）
- **請求日**：月末とは限らない。自由な日付で入れる
- 企業シートに書き込む直前に、同じ請求日・案件名の行がないかを確かめ、あれば書かずに知らせる（二重に書かないため）
- 明細の「企業シートに先付け記載済み」チェックは**作らない**（企業シートに手で先付けを書かなくなったため。11/01 夜）
- 企業のページの「請求状況」は「契約と回数」だけにする。前回の請求の中身は「請求の履歴」で見る。「この企業の請求をすべて見る」で、履歴を全部開いて出す
- 今は取引のない企業も、しばらくぶりに請求することがあるので、企業・履歴は消さずに残す
- 履歴の「未請求」：今月に請求する毎月の契約があり、アプリに今月の請求がまだない企業に出す（企業のページから「新規」）。入力中の請求も「未請求」（「開く」）

## フォームとExcelの対応（10/29 ひろみ確認）

| フォームの項目 | 企業シート | 売上表（月別シート・2行目〜） | 収支一覧の売上明細（「売上（NEW）」B〜I） |
| --- | --- | --- | --- |
| 企業 | シートの選択＋B クライアント名 | B 社名 | 社名 |
| 請求日 | A 請求日 | ― | ― |
| 計上月 | B クライアント名の「（◯月）」・H 計上月 | どの月のシートか（E列「発売日」は今までどおり「-」） | B 請求月（2611 のような年＋月の数字） |
| 内訳（案件名） | C 案件名 | D 内訳 | 内訳 |
| 単価・個数 | D 単価・E 個数 | F 個数・G 受注金額 | 受注金額 |
| 税込 | ― | H に請求書の合計（税込）を1行目にだけ | 請求金額（税込）に請求書の合計を1行目にだけ |
| 支払期限 | I 支払期限 | N 入金予定（2行目からは「〃」） | G 入金予定（2行目からは「〃」） |
| 備考 | G 備考 | ― | ― |
| 請求書№ | ― | C 請求書№ | ― |
| 担当 | ― | A 担当（「社長」か「担当」） | ― |
| 入金 | ― | O 入金確認・P 入金金額（空けておく。ひろみが記入） | 入金日・入金金額（空けておく。ひろみが記入） |

- 企業シートの売上金額（F =D×E）は今の計算式のまま。売上表の税込（H）は行ごとの式ではなく、請求書の合計を1行目にだけ（11/01）
- 転記は「今のファイルを渡す → 行を足したファイルが返る → 共有フォルダに上書き保存」。書式・既存の計算式・マクロ・ほかのシートは触らない
- 転記はブラウザの中で行い、Excelファイルはサーバーに送らない
- 請求ごと・ブックごとに「書き込み済み」を記録し、二重に書かない
- **企業シートは書く側**（11/01 夜に変更）：アプリが書き込むだけ。10/31 までの分は1回だけ取り込み済み（10/30 の「読む側」は取りやめ）
- **売上表は書く側**：請求したものを月ごとにまとめ、あとで入金確認（売掛）に使う。アプリは売上表からは読まない（10/30 決定）
- 旧Excelのぶんは「企業シートに記入済み（◯月分・◯回目まで）」とだけ出す。請求済みかどうかは出さない
- 企業のページに請求状況（契約ごとの回数・前回の請求）を出し、そこから当月の請求を入力する。明細の行は契約につなげて回数を数える（10/30）
- 明細が複数行の請求は、売上表・収支一覧にも明細の数だけ行を足す（企業シートと同じ。10/30 決定）
- **書き足す行**（11/03）：売上表・収支一覧とも、B列が空いているいちばん上の行から。セルの書式は、同じ列で上にある値のセルにそろえる。行の高さは今のまま。値や式の入っているセルには書かない（書き込みをやめる）
- **書き込み済みの記録**（11/03）：「Excelへの記入」の画面で、計上月ごとに、請求書を作った請求を書く。請求ごと・ブックごとに `bill_excel_writes` に1行（シート・何行目・ファイル名）。記録のある請求は書かない。ファイルの中に同じ請求（売上表は請求書№、収支一覧は請求月・社名・内訳）がもうあれば、それも書かない。ファイルを保存しなかったときなどは「記入を取り消す」で記録を消して、もう一度書く（Excelの行は手で消す）
- 書いたあとに「作り直す」で請求書を作り直したときは、画面に知らせを出す（Excelの行は手で直す）
- 書き足したファイルは、開いたときに式を計算し直す（収支一覧2027（NEW）の SUMIF など）
- **企業シートへの記入**（11/08）：「Excelへの記入」の画面の3つ目。企業シートのファイル（.xlsm）を選ぶと、請求ごとにその企業のシートを探して書き足す（マクロ・ほかのシートはそのまま）
  - シートの探し方：企業シートの取り込みのときにその企業の行があったシート → なければ、シート名・B2・明細の B クライアント名を企業名と別名で突き合わせる（表記ゆれは取り込みと同じ考え方で吸収）
  - 書く行：A 請求日か C 案件名のある、いちばん下の行の次から（B クライアント名が空いている明細の行があるため）。「売上合計」の行より上に収まらなければ書かない
  - 列は6行目の見出しの言葉で探す（ユニテクノのシートだけ H 粗利金額・I 計上月・J 支払期限）
  - B クライアント名：そのシートで今まで使ってきた社名の書き方＋「（11月）」（「（5月分）」と書いてきたシートは「（11月分）」）。H 計上月は「11月」（半角）
  - F 売上金額：空いている行に前もって入っている =D×E の式をそのまま使う。行がずれた式（=D11*E12 など）は、その行の式に直す
  - 同じ請求日・案件名の行がもうあれば、その請求は書かずに知らせる
  - その企業のシートが見つからないときは書かずに知らせる（新しい企業のシートをどう足すかは、まだ決めていない）
- **担当**（11/01 ひろみ決定）：フォームのプルダウンで「社長」「担当」から選ぶ。社長が入れたかどうか（責任の所在）を残すため。社長以外が入れたときは「担当」。名前は今は入れない

## 収支一覧ブック（10/29 確定）

セレッジの社長と、うちの社長（出資者）が収支を把握するための経営層向けのサマリ。

- 収支一覧表：1か月1行。請求月｜売上計（税込）｜利益（売上計−支出計）｜支出計｜月末振込｜海外送金｜人件費｜社会保険料｜クレジット｜経費｜その他
- 売上の明細（「売上（NEW）」シート）：アプリが追記。請求月（2611 のような年＋月の数字）を毎行に入れ、小計行は作らない（11/03：年の列はなくし、請求月の数字に年を入れる）
- **売上の明細の列（11/03 ひろみが作った形）**：B 請求月｜C 社名｜D 内訳｜E 受注金額｜F 請求額（税込）｜G 入金予定｜H 入金日｜I 入金金額。アプリが書くのは入金予定まで。入金日・入金金額はひろみが売掛を確かめて記入する（フォームには出さない）
- **売上表は年度ごとのブック**（11/01 ひろみ決定）：7月決算なので 2026年8月〜2027年7月が「売上表（2027年度）」。シート名は「8月」〜「7月」。2026年8〜10月のシートも新しいブックに移して1冊にまとめる
- **請求月**は「11月」のように書く（「末」は付けない。11/01 ひろみ決定）
- **行ごとの税込は書かない**（11/01 ひろみ決定）：請求書の消費税は、インボイス制度で一の請求書につき税率ごとに1回の端数処理（今は切り上げ）なので、行ごとの ×1.1 はまぎらわしい。その代わり、**請求書の合計（税込）を、その請求の1行目にだけ**入れる（売上表は H「税込」、収支一覧は「請求金額（税込）」の列。2行目からは空ける）。入金は請求書どおりの金額で来るので、入金額と1対1で見比べられるようにするため（11/01 ひろみ決定）。収支一覧の売上の明細は：年｜請求月｜社名｜内訳｜受注金額｜請求金額（税込）｜入金予定｜入金日｜入金金額
- **その月の合計**は、収支一覧表（1か月1行）に、売上の明細の「請求金額（税込）」を SUMIFS で足して出す（11/01 ひろみ決定。明細の途中に合計行は入れない。月の途中で行が増えても崩れないため）
- 支出の明細：月末支払いのシート。ひろみが今までどおり
- 売上計は同じブックの売上明細から SUMIFS で合計する（別ファイルへのリンクは使わない）
- **請求ベース。請求書を出した月が計上月**（11/01 ひろみ決定）。入金が翌々月などにずれても、計上月は動かさない。入金予定は行ごとに持つ
- アプリは、入力したときの計上月で、売上表の月別シートと収支一覧の売上明細に同じ月で書く
- 今の収支一覧にある「◯月入金予定」の見出しと合計は、ひろみ用の目印。アプリは読まない・書かない

## 請求

| 項目 | 決まったこと |
| --- | --- |
| 流れ | 「アプリに入力済み」（自由に直せる）→「請求書作成済み」（番号が付く）→「請求済み」（送った日・送り方を残す）。10/30 決定 |
| 状態の言葉 | かならず場所を入れる。アプリのことは「入力」、Excelのことは「記入」（例：アプリに入力済み、企業シートに記入済み）。10/30 決定 |
| 作ったあとに直す | 請求書作成済み・請求済みは直接は直せない。「作り直す」で入力中に戻して直す。番号はそのまま、前の版は残る。**線を引くのは「送った」**（11/04 ひろみ決定）：まだ送っていない請求書は、理由なしで作り直せて、消すこともできる（番号は飛ぶ。ひろみOK）。一度でも送ったものは、作り直すのに理由が要り、消せない。Excelに記入済みの請求は、記入を取り消すまで消せない |
| 二重 | 「請求書を作る」を二度押しても、番号も請求書も1つだけ |
| 請求書番号 | 自動採番。「年度2桁＋月2桁-その月の連番」。2026年11月の1枚目は 2711-01（10/30 このまま使うと決定） |
| 送り方 | 郵送／メール（セレッジ担当が直接送る）を、請求書ごとに選ぶ。企業の「いつもの送り方」が初期値 |
| 売上の月 | 請求ベース（請求した月の売上） |
| 消費税 | 請求書ごとに1回計算。端数は切り上げ。立替金などは「消費税がかからない」行 |
| 支払期限 | 初期値は翌月末。例外は入力時に直す |
| 書式 | 今のExcelと同じ並び。A4、角印、明細8行（9行以上は行を詰めて1枚に収める。請求書は1社1枚が基本で、別の請求書には分けない。11/03）。「消費税がかからない」行がある請求書だけ合計欄を「10％対象／消費税／対象外」に分ける |
| 封筒 | 長3。プリンターは Canon |
| 記録 | 作った人・作り直した人と日時を残す |

## 以前の決定で、使わなくなったもの（10/30）

- 請求依頼 → 売上 → 請求書の3段の作り。フォームの入力がそのまま請求書の下書きになる
- 送付OK・送付済みの流れと、それに合わせたペチちゃんの6条件（入力中は自由に直せる・作ったあとの変更は作り直し・二重に作らない・操作の記録、は v1.0 でも守る）
- 支払い・固定費・入金をアプリに入れる案

## まだ決めていないこと

- 請求を取り消したときの扱い。旧Excelでは、売上表は行を残して右端（Q列）に「請求取消」と書き、収支一覧には載せない（9月に実例あり）。アプリでどう扱うかは「各Excelへの記入」を作るときに決める
- 既にある月の請求に明細を足す（画像の「11月分の請求書に追加」）を、請求書作成済みのあとはどうするか（作り直し／別の請求書）
- 履歴を何か月ぶん出すか（今の作り：直近6か月を出し、それより前は「それより前の請求を見る」を開くと全部出る。ひろみに触ってもらって決める）

- 新しい企業のシートは、最初はひろみが手で1枚足すか（アプリで足すのはあとから）
- 請求書のない売上（甲賀市など）を、フォームから入れてExcelにだけ書くか
- 「前回と同じ内容で始める」ボタンが要るか（ゴゴからの提案）
- 立替金の行に付ける言葉：「非課税」のままか「対象外（立替金）」か（税理士に確認）
